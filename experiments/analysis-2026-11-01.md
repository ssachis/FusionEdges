- **The report roughly doubles the cost.** In both same-model pairs D used 1.75x and 2.2x the tokens of A. The
  report call alone is ~15k tokens: it re-reads the same ~7k tokens of code plus the scanner facts.
- The report call mostly restates the scanner facts in prose. The facts were already computed for free.
- Output is 25-30% of tokens and is mostly **whole files rewritten** (e.g. +563 lines for one Header), largely
  mechanical translation (types removed, `@/` imports rewritten, `next/link` swapped).
- A build repair re-sends the files: the one repair in the pilot cost +10k tokens.

So as built, D cannot win on cost; it can only win on correctness. That is why the cost question needs a different
intervention, not a shorter report.

## 2. What actually went wrong (all 8 runs)

| Failure seen | Run | Kind | Could a deterministic step prevent it? |
|---|---|---|---|
| Site's `main.js` throws on scroll: `.navbar` / `.navbar-default` removed | A, task 1 | host regression | **Yes**: keep the classes the scanner found (`host-script-coupling`) on a wrapper |
| Build fails: `Can't resolve './SearchButton'`, imported but never written | A, task 2 | missing file | **Yes**: copy the donor's import closure as files |
| Answer cut off, navbar never mounted, old navbar still shown | D, task 2 | missing mount | **Yes**: mount by repointing the imports of the existing navbar |
| Desktop links hidden: `md:flex` turned into inline `display:none` | D, task 3 | styling | **Yes**: compile the Tailwind utilities used, scoped, no preflight |
| Navbar unstyled: Tailwind classes on a site without Tailwind | A, task 4 | styling | **Yes**: same |

**5 of 5 observed failures were mechanical**: each matches a scanner fact the system had already found and each has a
rule-based fix. None needed judgement. Caveat: 4 tasks, 1 run each. This is a reason to test the idea, not proof.

What the model did that a rule cannot: drop donor features that cannot work in the host (the sign-in button needs
better-auth and a backend; search needs pliny/Next). The deterministic port copies them faithfully, so it pulls in
`better-auth`, `pliny` and React-19-only packages. That is the part to leave to the AI layer.

## 3. Weak spots in the evidence so far

1. **n = 4 tasks, 1 run each, 2 fair (same-model) pairs.** No uncertainty estimate is possible.
2. **The model was not pinned** (503 → fallback to flash-lite). Fixed in the held-out plan (pinned, no fallback).
3. **Checks changed after seeing the data** (v1 → v3 → v4). Fine for a pilot; frozen now for the held-out set.
4. **Two of the four repos are popular** (memorisation risk). The held-out set uses low-star repos.
5. **The cost comparison was never planned**: tokens are recorded but not analysed. H2 below fixes that.
6. **Report adherence is unmeasured**: we do not know if D's wins come from the report's advice or from luck.
   `adherence.py` exists; it should run on every D pair of the held-out set.

## 4. Change: deterministic port first, AI only for what is left

New module `fusionedges/port.py` (no AI). For each scanner fact it either resolves it or hands it to the AI layer:

| Scanner fact | Deterministic action |
|---|---|
| language (TS → JS) | TypeScript compiler strips types, keeps JSX |
| path-alias | `@/…` rewritten to relative paths |
| framework-api, routing-model, dependency-missing (`next`) | `next/link`, `next/image`, `next/navigation`, `next/font`, `next/dynamic`… import a generated `next-shims.jsx` built on the site's own router (v5, v6 or plain links) |
| missing packages | added to package.json at the donor's versions |
| styling-system, global-selector-leak | Tailwind CLI compiles only the utilities the component uses, no preflight, every rule behind `.fe-navbar`; donor theme variables scoped the same way; donor global CSS never copied |
| host-script-coupling | wrapper `<div class="fe-navbar navbar navbar-default">` keeps what the site's scripts look up |
| mount, slot-occupied | imports of the site's existing navbar repointed to the fusion entry; else the inline `<header>`/`<nav>` in App is replaced; else inserted at the top of App |
| assets | `/public` images the component references copied |

Everything lands in `src/fusion/navbar/`, so the diff is easy to review and to delete.

**Offline run on the 4 pilot pairs** (port only, no build: this machine has no npm access):
- 7–9 facts resolved per pair; all 4 mounted by repointing the existing navbar's import; 42 ported files, 0 syntax
  errors (TypeScript parser).
- Left for the AI layer: Tailwind (needs npm here), React 19 vs 17/18, env vars (`BASE_PATH`), and the
  backend-bound features above.
- **0 tokens.** If the AI layer is needed, its message is ~13k characters (≈6k tokens) instead of A's ~25k
  characters, and it asks for a small change, not whole files.

New conditions (pre-registered in `heldout-plan-2026-10-27.md`, "Changes after freezing"):
- **M**: port only, 0 tokens. **MA**: port, then the model only if build/browser fails or a fact is left (≤2 calls).
- **H2**: MA succeeds at least as often as A and uses ≥50% fewer tokens.
