ONE-TIME SETUP

Connect GitHub your way.

Quick local demo: fine-grained token

  1. On GitHub, open Settings → Developer settings → Personal access tokens → Fine-grained tokens.
  2. Create a token with an expiry and access only to the target repositories you want to change.
  3. Give it repository permissions: Contents: Read and write, Pull requests: Read and write, and the required metadata access.
  4. Return to FusionEdges and use “Connect with a fine-grained GitHub token.” The token is kept only in this server’s memory.

For public donors outside the token’s selected repositories, reading the donor falls back to anonymous GitHub access. Private donors are not supported in this version.

Organization policies can require approval or restrict token access. A valid sign-in does not automatically grant repository write access.

Product sign-in: GitHub App

  1. Register a GitHub App in GitHub’s Developer settings.
  2. Set its homepage to http://127.0.0.1:8101/projects and its user-authorization callback URL to http://127.0.0.1:8101/auth/github/callback.
  3. Enable user authorization. Webhooks and a private key are not needed for this user-token flow.
  4. Give the app Contents: Read and write and Pull requests: Read and write. Install it on selected target repositories.
  5. In the terminal that starts the feature server, configure FUSIONEDGES_GITHUB_CLIENT_ID, FUSIONEDGES_GITHUB_CLIENT_SECRET, and FUSIONEDGES_GITHUB_APP_SLUG. Keep the secret out of Git and chat.
  6. Restart only this feature server, then choose “Continue with GitHub.”

Sign-in uses state verification and PKCE. The app can access only resources available to both the user and its installation. Sessions expire; reconnect if needed.

What approval does

FusionEdges pins both repositories, prepares the integration locally, and shows the diff and verification results. After your explicit approval it creates a new branch and opens a draft PR against the target’s default branch. It does not push to the default branch or merge the PR.

This is a local development prototype. Repository build scripts run on this computer only after your confirmation. Private code requires separate consent before it is sent to the configured AI provider. Use trusted repositories.
